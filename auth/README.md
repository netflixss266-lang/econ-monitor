# ระบบบัญชีผู้ใช้ — คู่มือติดตั้ง

โครงทั้งหมดเขียนไว้แล้วและกดใช้งานได้ในเครื่อง เหลือขั้นตอนที่ต้องทำในบัญชี Supabase
ของเจ้าของเว็บเอง เพราะการสมัครบริการต้องกรอกอีเมลกับรหัสผ่านของคุณ

รวมเวลาที่ต้องใช้ประมาณ **20–30 นาที** ทำครั้งเดียวจบ

---

## ไฟล์ในโฟลเดอร์นี้

| ไฟล์ | คืออะไร |
|---|---|
| `schema.sql` | ตาราง `profiles` กับ `login_events` สิทธิ์รายแถว และงานลบข้อมูลเมื่อครบ 90 วัน |
| `functions/log-login/index.ts` | Edge Function อ่าน IP จริงจาก header แล้วบันทึกลง `login_events` |
| `auth.js` | ตัวกลางระหว่างหน้าเว็บกับระบบบัญชี มีสองร่าง: ทดลอง กับ Supabase จริง |
| `account.html` | เข้าสู่ระบบ / สมัคร / ลืมรหัสผ่าน / ตั้งรหัสใหม่ / ประวัติการเข้าใช้ |
| `privacy.html` | นโยบายความเป็นส่วนตัว ฉบับร่าง |

---

## ลองดูหน้าตาก่อน (ไม่ต้องสมัครอะไรเลย)

```bash
cd D:\DJ\Git\econ-monitor
python -m http.server 8000
```

เปิด `http://localhost:8000/auth/account.html` จะขึ้นแถบ **โหมดทดลอง**
ข้อมูลอยู่ในเบราว์เซอร์เครื่องนั้นเท่านั้น ไม่ส่งออกไปไหน และ IP ที่เห็นเป็นเลขสมมติ

ร่างทดลองทำงานเฉพาะบน `localhost` เท่านั้น ถ้าเปิดจากเว็บจริงหน้าจะขึ้นว่า
"ยังไม่เปิดใช้งาน" และปิดช่องกรอกทั้งหมด กันคนเข้าใจผิดว่าสมัครกับเว็บจริงไปแล้ว

# ขั้นตอนต่อของจริง

## ขั้นที่ 1 · สร้างโปรเจกต์ Supabase — 5 นาที

1. ไปที่ [supabase.com](https://supabase.com) กด **Start your project**
2. เข้าด้วยบัญชี GitHub ที่ใช้อยู่ได้เลย ไม่ต้องตั้งรหัสผ่านใหม่
3. กด **New project** แล้วกรอก
   - **Name** — `tribune`
   - **Database Password** — กดปุ่มสุ่มแล้ว **เก็บใส่ที่ปลอดภัยไว้**
     รหัสนี้ใช้ตอนต่อฐานข้อมูลตรงๆ ไม่ได้ใช้ในเว็บ และกู้คืนไม่ได้ถ้าลืม
   - **Region** — เลือก **Southeast Asia (Singapore)** ใกล้ผู้ใช้ไทยที่สุด
   - **Plan** — Free
4. รอสร้างเสร็จประมาณ 2 นาที

## ขั้นที่ 2 · สร้างตาราง — 2 นาที

1. เมนูซ้าย → **SQL Editor** → **New query**
2. เปิดไฟล์ `auth/schema.sql` ก๊อปทั้งไฟล์มาวาง
3. กด **Run** (หรือ Ctrl+Enter) ต้องขึ้น `Success. No rows returned`
4. ตรวจว่าได้จริง: เมนูซ้าย → **Table Editor** ต้องเห็นตาราง `profiles`
   กับ `login_events` และมีป้าย **RLS enabled** สีเขียวอยู่ข้างชื่อทั้งคู่

> ถ้าป้าย RLS ไม่ขึ้น แปลว่าสคริปต์รันไม่ครบ ให้รันซ้ำอีกรอบ
> ตารางที่ไม่มี RLS = ใครก็อ่านข้อมูลคนอื่นได้ ห้ามข้ามข้อนี้

## ขั้นที่ 3 · ตั้งค่าระบบบัญชี — 5 นาที

**3.1 เปิดการสมัครด้วยอีเมล**
เมนูซ้าย → **Authentication** → **Sign In / Providers** → **Email**
- เปิด **Enable email provider**
- เปิด **Confirm email** — บังคับยืนยันอีเมลก่อนใช้งานครั้งแรก
- **Minimum password length** ใส่ `10` ให้ตรงกับที่หน้าเว็บตรวจไว้

**3.2 ตั้ง URL ให้ลิงก์ในอีเมลเด้งกลับมาถูกที่** *(ข้อนี้ลืมบ่อยที่สุด)*
**Authentication** → **URL Configuration**
- **Site URL**

  ```
  https://netflixss266-lang.github.io/econ-monitor/
  ```

- **Redirect URLs** กด Add URL แล้วใส่ทีละบรรทัด

  ```
  https://netflixss266-lang.github.io/econ-monitor/auth/account.html
  http://localhost:8000/auth/account.html
  ```

  บรรทัดที่สองไว้ทดสอบในเครื่อง ถ้าไม่ใส่ ลิงก์ยืนยันอีเมลกับลิงก์ตั้งรหัสใหม่
  จะเด้งไปหน้าว่างหรือขึ้น error

**3.3 เรื่องอีเมลที่ต้องรู้**
Supabase ให้ส่งอีเมลฟรีแค่ **ประมาณ 3 ฉบับต่อชั่วโมง** เพราะเป็นเซิร์ฟเวอร์ทดสอบ
พอเริ่มมีคนสมัครจริงต้องไปต่อ SMTP ของตัวเอง (Resend หรือ Brevo มีโควตาฟรีพอ)
ที่ **Project Settings → Authentication → SMTP Settings**
ตอนทดสอบเองไม่กี่คนยังไม่ต้องทำ

## ขั้นที่ 4 · ติดตั้ง Edge Function — 5 นาที

ตัวนี้คือส่วนที่อ่าน IP จริง เลือกทางไหนก็ได้

### ทาง ก · ผ่านหน้าเว็บ Supabase (ง่ายกว่า ไม่ต้องลงอะไรในเครื่อง)

1. เมนูซ้าย → **Edge Functions** → **Deploy a new function** → **Via editor**
2. ตั้งชื่อว่า **`log-login`** (ต้องตรงตัวนี้เป๊ะ ไม่งั้นหน้าเว็บเรียกไม่เจอ)
3. ลบโค้ดตัวอย่างทิ้ง แล้ววางเนื้อไฟล์ `auth/functions/log-login/index.ts` ลงไปทั้งไฟล์
4. กด **Deploy**

### ทาง ข · ผ่าน CLI

ต้องมี Node.js ในเครื่อง และไฟล์ต้องอยู่ในโฟลเดอร์ชื่อ `supabase/functions/log-login/`
ตามที่ CLI กำหนด

```bash
npx supabase login
npx supabase link --project-ref <project-ref ของคุณ>
mkdir -p supabase/functions/log-login
cp auth/functions/log-login/index.ts supabase/functions/log-login/index.ts
npx supabase functions deploy log-login
```

`project-ref` คือตัวอักษรชุดกลางของ Project URL เช่นถ้า URL เป็น
`https://abcdefghijk.supabase.co` ค่านี้คือ `abcdefghijk`

### ตั้งค่าลับให้ฟังก์ชัน

**Edge Functions** → **Secrets** → Add new secret

```
SITE_ORIGIN = https://netflixss266-lang.github.io
```

ส่วน `SUPABASE_URL` กับ `SUPABASE_SERVICE_ROLE_KEY` Supabase ใส่ให้เองอัตโนมัติ
**ไม่ต้องเพิ่มเอง และห้ามเอา service_role key ไปแปะที่อื่นเด็ดขาด**

## ขั้นที่ 5 · ใส่คีย์ในหน้าเว็บ — 2 นาที

1. **Project Settings** → **API Keys** ก๊อป 2 ค่านี้
   - **Project URL** เช่น `https://abcdefghijk.supabase.co`
   - **anon / public key** (ตัวยาวที่ขึ้นต้นด้วย `eyJ...`)
2. เปิด `auth/auth.js` แก้ตรงหัวไฟล์

   ```js
   const CONFIG = {
     url: "https://abcdefghijk.supabase.co",
     anonKey: "eyJhbGciOi...",
     logFn: "log-login",
   };
   ```

3. commit แล้ว push — `auth.js` จะสลับจากร่างทดลองไปใช้ Supabase ให้เองอัตโนมัติ
   เมื่อเห็นว่ามีค่าใน `url` แล้ว

### เรื่องคีย์ที่ต้องแยกให้ออก

| คีย์ | เอาไปไว้ไหนได้ | อันตรายไหม |
|---|---|---|
| **anon / public** | ในโค้ดหน้าเว็บ commit ขึ้น GitHub ได้ตามปกติ | ไม่ — ความปลอดภัยมาจากสิทธิ์รายแถวในฐานข้อมูล ไม่ได้มาจากการซ่อนคีย์ |
| **service_role** | ใน Edge Function เท่านั้น | **อันตรายมาก** — ข้ามสิทธิ์ทุกอย่างในฐานข้อมูล ห้าม commit ห้ามส่งให้ใคร รวมถึงห้ามส่งให้ผม |

## ขั้นที่ 6 · เปิดงานลบข้อมูลอัตโนมัติ — 2 นาที

นโยบายความเป็นส่วนตัวประกาศไว้ว่าเก็บประวัติ 90 วัน ถ้าไม่ตั้งข้อนี้
ข้อมูลจะค้างตลอดกาลและกลายเป็นทำไม่ตรงกับที่ประกาศไว้

1. **Database** → **Extensions** → ค้นหา `pg_cron` → เปิด
2. **SQL Editor** รันคำสั่งนี้

   ```sql
   select cron.schedule('purge-login-events', '17 3 * * *',
                        $$select public.purge_old_login_events()$$);
   ```

3. ตรวจว่าตั้งสำเร็จ

   ```sql
   select jobname, schedule, active from cron.job;
   ```

## ตรวจว่าใช้ได้จริง

ทำตามลำดับนี้ ถ้าผ่านครบแปลว่าเสร็จสมบูรณ์

1. เปิด `https://netflixss266-lang.github.io/econ-monitor/auth/account.html`
   → แถบ "โหมดทดลอง" ต้อง **หายไปแล้ว**
2. สมัครด้วยอีเมลจริงของตัวเอง → ต้องได้อีเมลยืนยันภายในไม่กี่นาที
3. กดลิงก์ในอีเมล → เด้งกลับมาที่หน้าบัญชี
4. เข้าสู่ระบบ → ต้องเห็นตารางประวัติการเข้าใช้ มี **IP จริง** ของคุณ ไม่ใช่ `203.150.11.x`
5. ลองใส่รหัสผิดหนึ่งครั้ง แล้วเข้าใหม่ → ต้องเห็นแถว "รหัสผิด" เพิ่มขึ้นมา
6. ใน Supabase → **Table Editor** → `login_events` ต้องเห็นแถวเดียวกัน
   และคอลัมน์ `ip_prefix` ต้องเป็นเลขตัดท้ายเช่น `203.150.11.0`
7. ลองกด "ลืมรหัสผ่าน" → เปิดลิงก์ในอีเมล → ต้องมาโผล่หน้า "ตั้งรหัสผ่านใหม่"

### ถ้าติดตรงไหน

| อาการ | สาเหตุที่พบบ่อย |
|---|---|
| กดลิงก์ในอีเมลแล้วขึ้นหน้าว่าง / `redirect_to is not allowed` | ยังไม่ได้ใส่ URL ในขั้นที่ 3.2 |
| เข้าสู่ระบบได้ แต่ตารางประวัติว่าง | Edge Function ยังไม่ได้ deploy หรือชื่อไม่ใช่ `log-login` เป๊ะ |
| ประวัติขึ้น แต่ IP เป็น `null` | ปกติถ้าเรียกจาก localhost — ต้องทดสอบผ่านเว็บจริง |
| อีเมลยืนยันไม่มา | ชนโควตา 3 ฉบับ/ชม. ของ Supabase → รอ หรือต่อ SMTP เอง (ข้อ 3.3) |
| `Failed to fetch` ตอนบันทึกประวัติ | `SITE_ORIGIN` ในขั้นที่ 4 ไม่ตรงกับโดเมนที่เปิดอยู่ |

## ยังไม่ได้ทำในรอบนี้

- ยังไม่มีลิงก์เข้าหน้าบัญชีจากหน้าเว็บหลัก — ตั้งใจไว้แบบนั้นจนกว่าจะต่อของจริงเสร็จ
- จำกัดจำนวนครั้งที่ลองรหัสผ่านแบบเข้มกว่าของ Supabase ที่ให้มา
- ซิงก์รายการโปรดกับอินดิเคเตอร์ขึ้นบัญชี — ตารางเตรียมคอลัมน์ไว้แล้ว รอรอบที่ 3
- ยืนยันสองชั้น และแจ้งเตือนเมื่อเข้าใช้จากประเทศใหม่ — รอบที่ 4
